# 科目分類データの設計

## 正規データ

卒業要件判定と科目一覧の分野表示に用いる科目分類は、次の学生便覧CSVを正とする。

- [`docs/【学生便覧】科目一覧（カリキュラム・マップ）_20260401 - 科目一覧.csv`](./【学生便覧】科目一覧（カリキュラム・マップ）_20260401%20-%20科目一覧.csv)
- 基準日: 2026年4月1日

公開シラバスの科目コードやプレフィックスは分類の根拠には使用しない。
CSVに未掲載の科目だけ、従来の科目コード推論をフォールバックとして使用する。

## CSV列とアプリ内データの対応

| CSV列 | アプリ内データ | 用途 |
| --- | --- | --- |
| `科目区分` | `band` | 導入・基礎・展開・卒業プロジェクト・自由科目の判定 |
| `科目分類` | `expansionTrack` | 基盤リテラシー・多言語情報理解・世界理解・社会接続のゲージ集計 |
| `学問分野` | `foundationGroups` | 基礎科目の数理・情報・文化思想・社会ネットワーク・経済マーケット等のゲージ集計 |
| `学問分野` | `fieldCategory` | 科目一覧の分野フィルター |

`foundationGroups` は基礎科目だけに設定し、`expansionTrack` は展開科目だけに設定する。
自由科目は `countableToGraduation: false`、それ以外は `true` とする。

## データ生成

`npm run build:data` は次の順序で `src/data/courses.json` を生成する。

1. 公開シラバスのMarkdownから科目の基本情報を抽出する。
2. CSVを標準CSVとして解析する。改行を含むヘッダーもCSVパーサーで処理する。
3. 正規化した科目名でCSVと照合し、科目コードも一致する場合は科目コード一致として記録する。
4. CSVの `科目区分`、`科目分類`、`学問分野` で分類情報を上書きする。
5. CSVに未掲載の科目だけ、科目コードによるフォールバック分類を残す。

科目名を照合の基準にするのは、CSVと公開シラバスで一部の科目コードが異なるためである。
UnicodeをNFKCへ正規化し、空白を除去して表記ゆれを吸収する。
科目名が一致しない科目コードだけでは、別科目を誤って対応付ける可能性があるため照合しない。

2026年4月1日版では、280科目のうち263科目が科目コード・科目名とも一致し、
17科目は科目名で照合される。アプリにある「ゼミ（生命と文化）」はCSV未掲載のため、
現在は科目コードによるフォールバック分類を使用する。

## 2026年9月の修正内容

科目コードのプレフィックスを分類に利用していたため、CSVとの不一致が22科目あった。
CSV適用後は、掲載280科目の分類がすべて一致する。

主な修正は次のとおり。

- 「データサイエンス概論」の基礎科目分野を数理から情報へ変更
- デジタル産業の展開科目11科目を基盤リテラシーから世界理解へ変更
- デジタル産業史4科目を基礎科目から展開科目・世界理解へ変更
- 機械翻訳6科目を基礎科目から展開科目・多言語情報理解へ変更

これにより、生成データの内訳は基礎科目16科目、展開科目245科目となる。

## 検証

`npm run validate:data` では以下を検証する。

- CSV掲載280科目の `band`、`foundationGroups`、`expansionTrack`、`fieldCategory`、`countableToGraduation`
- CSVの全行が生成データのいずれかの科目に対応していること
- 「データサイエンス概論」だけを配置すると情報分野が2単位増えること
- 「データサイエンス概論」が数理分野へ誤加算されないこと
- 「コンテンツ産業論」と「ゲーム制作論基礎」を配置すると世界理解が4単位増えること
- 上記2科目が基盤リテラシーへ誤加算されないこと

`npm run build` には `validate:data` が組み込まれているため、分類不一致がある場合はビルドを失敗させる。

## 更新手順

学生便覧の科目一覧が更新された場合は、次の順序で対応する。

1. `docs/` 直下の科目一覧CSVを新しい版へ差し替える。
2. 同時に複数の科目一覧CSVを置かない。
3. `npm run build:data` を実行する。
4. 未掲載科目と科目名照合件数を確認する。
5. `npm run validate:data` と `npm run build` を実行する。
6. 本文書の基準日、照合件数、未掲載科目を更新する。
