# AI相談とインポートデータの仕様

## 目的

「AIに相談」で生成するプロンプトは、利用者向けの履修提案と、履修計画プランナーが確実に読み込める機械可読データを同時に回答させます。Markdown表は人が提案を確認するために使い、インポート処理は回答末尾のJSONコメントを正規データとして使います。

## プロンプトに渡す情報

- 利用者が入力した希望
- 配置済み科目の年次、Q、科目ID、科目名
- 現在不足している卒業要件
- アプリが保持する全科目の科目ID、科目名、開講年度、履修想定年次、開講Q、単位、科目分類、学問分野、タグ、前提科目
- 配置可能な最大年次

AIには、カタログに存在しない科目を作らないこと、配置済み科目を再提案しないこと、開講Qと前提科目を確認することを指示します。
プロンプトはSlackへ貼り付けられるよう4万文字未満に保ち、公式シラバスURLは開講年度と科目IDから組み立てる規則を渡します。

## 利用者に案内する調べ方

AIの回答には、候補ごとの公式シラバスURLと、次の再確認手順を含めます。

1. 公式シラバスで科目名、概要、開講Q、授業方法、評価方法、前提科目を確認する。
2. 学生便覧のカリキュラム・マップで、分野・科目分類・卒業要件への算入を確認する。
3. 確認できない候補は断定せず、インポート用データへ含めない。

## インポート用JSONコメント

AIは回答の最後に、コードフェンスで囲まず次の形式を出力します。

```text
<!-- IMPORT_DATA_START
{"version":"1.0","planName":"AIおすすめ追加案","plannedCourses":[{"courseId":"INT-1-A1-1030-003","year":1,"quarter":1,"note":"おすすめ理由"}]}
IMPORT_DATA_END -->
```

`plannedCourses`には今回追加する科目だけを入れます。`year`と`quarter`は文字列ではなく整数です。`note`は任意の文字列で、AI相談画面から追加した場合は履修計画にも保持されます。

## インポート時の検証

インポーターはJSONコメントを最初に解析し、次を検証します。

- `plannedCourses`が空でない配列であること
- `courseId`がアプリの科目データに存在すること
- `year`が1以上かつ計画の最大年次以下の整数であること
- `quarter`が1〜4の整数であること
- 配置Qが科目の開講Qに含まれること
- 同一科目IDが重複していないこと
- AI相談からの追加時は、すでに計画へ配置済みの科目でないこと
- `note`が指定されている場合は文字列であること

JSONコメントがあるのに壊れている場合、Markdown表へ暗黙にフォールバックせずエラーを表示します。これにより、AI回答の一部だけが誤って取り込まれることを防ぎます。過去のAI回答との互換性のため、JSONコメントがない場合に限り従来のMarkdown表も解析します。

## 自動検証

`npm run validate:ai`で、プロンプトに必要な指示と科目情報が含まれること、正常なAI回答を読み込めること、未知の科目IDと不正JSONを拒否することを検証します。この検証は`npm run build`にも含まれます。
